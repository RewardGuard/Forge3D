Operator guide

Running the F3D Storage host.

This page is for whoever runs the storage host. Customers never need any of it — for them F3D Storage is just space that works.

How it fits together

One machine — the host — has the storage drives attached and serves every customer's files from them. It dials out to forge3d.design and holds the connection open, so it works behind any router with no port forwarding and no fixed IP.

Each customer gets their own folder, named after a hash of their email, so the folder name never reveals who they are and one customer can never reach another's files.

Drives

Preparing one

  1. Plug in the drive you want to dedicate.
  2. Open Disk Utility, erase it, and name it exactly F3D_STORAGE.
  3. That's it — the app picks it up automatically. It never formats a drive for you.

Adding more space

Name each additional drive F3D_STORAGE_2, then _3, and so on. New uploads always go to whichever drive has the most free space, so you can add capacity without moving anything that's already stored.

When to add one

At 96 GB used the host raises a macOS notification. That threshold leaves room to order and plug in the next drive before anything is tight. Uploads keep working past it — the only hard stop is the drive physically running out, and a write that wouldn't fit is refused up front rather than leaving a half-written file.

Surviving power cuts

The host reconnects on its own, but two macOS settings decide whether it comes back unattended:

SettingWhy
System Settings → Energy →
"Start up automatically after a power failure"		 Otherwise the Mac simply stays off and the service is down until someone presses the power button.
Keep the login session unlocked The host's signing key lives in the Keychain, which needs an unlocked session. This is exactly what makes the key uncopyable — the tradeoff is that a locked Mac can't host.

The app itself reopens at login automatically once it has confirmed it's the host.

Security model

Hosting requires all three at once — any one alone is useless:

  • the operator account,
  • the pinned machine (fixed on first connection),
  • a fresh signature from a key that lives in that Mac's Keychain.

So a copied account token on another computer is refused, an old captured signature can't be replayed, and a forged one fails. To move hosting to a different machine you delete host-pin.json on the server — a deliberate, physical act.

Handy commands

Which drives are visible right now:

ls -1 /Volumes | grep F3D_STORAGE

Space used and free per drive:

df -h /Volumes/F3D_STORAGE*

How many customers are stored:

ls -1 /Volumes/F3D_STORAGE/customers 2>/dev/null | wc -l

If something looks wrong

SymptomWhat it means
Panel doesn't show HOSTNo drive named F3D_STORAGE is mounted. Reconnect it.
"Reconnecting…" for a whileNetwork is down or the IP just changed. It redials on its own within about half a minute.
Customers see "temporarily offline"The host Mac is off, asleep, or locked. No data is lost — files are still on the drives.
Host refuses to registerMachine or key doesn't match the pin. Expected on a new Mac; delete host-pin.json on the server to re-pin.
